# Fare finder: зафиксированные решения

Термины — в `GLOSSARY.md`. Здесь только решения из сессии гриллинга.

## Решено

**Цель и границы**
- Общий интерфейс `FareSource` для всех источников (RyanAir, Wizz Air, позже другие). Источник — `FareSource`, не авиакомпания.
- Сейчас проектируется только сервисный слой. Веб-интерфейс — отдельный слой поверх него.

**Общий блок параметров (Q3, Q7, Q11, Q22)**
- Общие параметры: аэропорт вылета, необязательный аэропорт прилёта, диапазон дат вылета, тип поездки (в одну сторону / туда-обратно), тип отдыха, дни недели, окно времени вылета, валюта, макс. цена.
- Общий блок формы: только пересекающиеся фильтры — аэропорт вылета, период, тип поездки.
- Пассажиры: захардкожены в 1, в форме не показываются.
- Общий результат `Fare` — плоская запись: источник, вылет, прилёт, дата вылета, дата возвращения (пустая для одной стороны), цена, валюта, идентификатор рейса.

**Параметры поставщиков (Q12, Q16, Q25)**
- Параметры, которых нет у поставщика, не отбрасываются. Они остаются в отдельном блоке формы этого поставщика.
- Точная дата — только в блоке RyanAir (галочка, по умолчанию выключена). Если выключена, период — месяцы, каждый месяц берётся от первого до последнего дня.

**Запуск поиска (Q15, Q16)**
- У каждого поставщика своя кнопка и свой поиск. Поиски не смешиваются и не запускаются параллельно.
- Результаты показываются отдельными таблицами, по одной на поставщика.

**RyanAir (Q5, Q6, Q21, Q23)**
- Адаптер `RyanAirFareSource` реализует `FareSource`. Существующее поведение сохраняется, это зафиксировано тестами.
- Поддерживается точный диапазон дат.
- Значения `ArrivalCategory` берём из enum и проверяем тестами.

**Wizz fare finder (Q17, Q18, Q19, Q20, Q21, Q23, Q24)**
- Fare finder = `SmartSearchCheapFlightsV2`: аэропорт вылета, список месяцев, `arrivalStations: null` (любое направление), тип поездки и длительность.
- Серверные фильтры в блоке Wizz: аэропорт вылета, месяцы, тип поездки, длительность (`anytime`, `weekend`), пассажиры.
- Дополнительные фильтры на нашей стороне (дни недели, время, цена) пока не делаем.
- `fareFind` собирает запрос из параметров формы. Эталон формата — живой пример в `makeWizzAirApiCall`.
- Живой запрос Wizz пробуем с текущими заголовками и исправляем по ошибкам.

**Веб-интерфейс (Q4, Q13, Q14, вердикт прототипа)**
- Встроенный `com.sun.net.httpserver` и статическая HTML-страница с JavaScript, без новых зависимостей.
- По умолчанию показывается последний снимок из `data/`. Кнопка «обновить» запускает живой поиск.
- Вариант макета — A, «стек»: общий блок, затем блок каждого поставщика с фильтрами и результатами по очереди. Таблица результатов на всю ширину, один рейс в строке.
- Прототип: ветка `prototype/fare-finder-layout`, коммит `2823485`.

**Порядок работы (Q10)**
- Сначала характеризационные тесты на текущее поведение RyanAir, потом выделение общих типов и адаптера.
